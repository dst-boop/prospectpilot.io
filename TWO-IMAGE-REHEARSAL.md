# Distinct successor diagnostic rehearsal

This draft keeps #138 frozen. It does not authorize deployment, production migration, floor registration, or release approval.

## Evidence sought

Build two independently pinned source trees into distinct immutable local image IDs. The floor is exact #138; the successor must contain a real reviewed product change, not a tag, test-only delta or relabeled image. The same test-only phase script is added in an overlay on each independently built image without replacing application modules. No host application source is mounted into a running image.

The successor accepts synthetic application writes in a randomly generated disposable PostgreSQL schema, then terminates. A bounded receipt identifies that fixture and a digest of persisted data; it carries no person data or identity key. The floor independently loads its own application code, checks strict034 admission and unchanged successor-written records before further mutations, and exercises ownership, advice, DNC, historical identity, deletion, idempotency and queued-reservation protections. Providers are denied by a strict Node network guard. Authentication is injected synthetic authentication, not Firebase. Normal workers are not run.

## Product compatibility is a separate verdict

The genuine proposed successor incorporates #136's same-name sponsor / distinct-EIN correction. Frozen #138 does not contain that change. Preserving stored arrays is not enough: new discovery can revert to an older sponsor selection, and the older UI can hide ambiguity context. The diagnostic must expose this difference and must not call narrower data/security preservation proof a fully compatible rollback. A successful diagnostic run does not approve this pair for production return.

## Limits

All database data, roles and requests are synthetic. Test images are local CI artifacts, not published registry provenance. Production inventory, writer draining, backup/PITR, accepted-work recovery, real sessions, worker execution and operational authorization remain unverified. The029 backup restore rehearsal is a different preactivation-only scenario and is not used to discard accepted successor writes here.
