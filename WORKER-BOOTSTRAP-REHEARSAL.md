# Actual worker: bounded idle and guarded-refusal rehearsal

This separate draft does not modify or approve the frozen reviewed floor, successor or negative controls. It builds the exact corrected candidate floor139 and overlays test instrumentation only, then runs the actual rollback-worker entrypoint with a disposable034 schema and generated synthetic role.

## Limited behavior to verify

The real worker must hold its schema guard while entering its idle loop. A controlled fixture barrier demonstrates loop execution, rather than treating a live process as proof. Guard loss must terminate the process. Incompatible035 startup must refuse work.

A separate synthetic legacy research task must reach the actual worker's identity-protection refusal, without calling any provider. Other stored advice and non-runnable pending/leased reservations must remain unchanged. No lab schedule, autopilot run or paid/provider job is made runnable. The strict network preload permits only the exact disposable database socket and denies credential/provider traffic; the child receives no real credentials.

## Limits

This establishes only actual entrypoint idle/refusal behavior if native CI passes. It does not validate normal paid job processing, successful provider calls, live schedules, real Firebase, production permissions, writer completeness, operational recovery, published image provenance or floor approval. Synthetic refused work is not evidence that arbitrary live queued work is safe to replay.

## Cleanup boundary

Normal completion and ordinary failures attempt cleanup of only the child and its generated role/schema. A hard process/container timeout can bypass that cleanup. The dedicated CI job therefore uses an ephemeral PostgreSQL service that is discarded at job end; a timed-out local disposable database must not be reused without inspecting/removing that run's synthetic fixtures or replacing the test service. The host does not broadly delete unknown roles to conceal incomplete cleanup. No production resource is involved.
