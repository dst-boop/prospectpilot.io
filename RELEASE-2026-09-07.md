## Delivered

- The authenticated home page is a research dashboard with discovery controls, daily scheduling, source economics, an evidence review queue, imports, and research CSV exports.
- Four independent qualification criteria: age strictly above 55; US residence; retained individual employer-plan assets with an available IRA-eligible distribution; and a recently reviewed contact route. Each records its reviewer, source, observation date and evidence note. Unknown, estimated, expired, conflicting and confirmed facts are distinct.
- DOL Form 5500 / Schedule H / 5500-SF ingestion, joined by filing ACK_ID and deduplicated by sponsor EIN, plan number and plan-year start. Average account balances use net plan assets and participants with account balances. Missing denominators and unreported fields remain unknown. No personal balances are inferred.
- Automatic official-site discovery and public biography extraction, SEC proxy candidate extraction and existing WARN employer evidence. Optional Brave Search requires a server-side subscription and an explicitly configured per-query cost. Imported ZoomInfo / WealthFeed / permitted LinkedIn exports use the existing subscription model.
- PostgreSQL-backed tasks, leases, replay protection and daily schedules survive a closed browser. Free interrupted tasks can recover; interrupted paid calls are not automatically repeated. A transaction reserves configured search cost before every paid request and enforces the daily limit across workers.
- Separate newly sourced, imported, duplicated, rejected, ambiguous and verified counts. A person is counted once when first qualified; expired or corrected qualifications are removed from current verified totals. Labor, infrastructure, provider and allocated subscription costs can be recorded. Cost per verified lead is unknown when there are no verified leads.
- Recently researched catalog employers rotate out of the automatic seed list for seven days. Explicitly named employer campaigns remain available.
- The prior discovery, research, provider import, lead assignment, Salesforce export and suppression workflows remain in the source application. The Lab itself sends no outreach.

## Deploy using the existing Google Cloud environment

Use an authenticated Google Cloud Shell with access to `lead-qualifier-505002`. Work in a fresh checkout so an older prepared deployment folder is preserved:

```bash
git clone https://github.com/dst-boop/prospectpilot.io.git prospectpilot-research-lab
cd prospectpilot-research-lab
REFRESH_PLAN_CATALOG=1 bash release.sh
```

The existing `prospectpilot` service, `prospectpilot-migrate` job, builder identity, PostgreSQL connectivity, secrets and Firebase sign-in configuration must exist. The release builds the Docker image with tests, applies additive migrations, optionally runs a separate public DOL catalog ingestion job, provisions the research worker/recovery scheduler, updates the service and verifies the unique release identifier through `https://prospectpilot.io/version`. A login-page response alone is not treated as proof of deployment.

Catalog ingestion uses a temporary 2-CPU / 4-GiB job because the full national datasets are large. It downloads only official public DOL files and logs aggregate counts. It is an occasional ingestion cost, not a daily per-lead charge. Later releases can omit `REFRESH_PLAN_CATALOG=1`; rerun it when refreshing the public catalog.

The release prints the previous image before modifying the service. If a release fails, preserve the output and do not assume the website changed. Roll back the service image using the printed prior image; migrations are additive.

After deploying, sign in at ProspectPilot, import the desired private lead CSVs, run **Assess saved leads**, and start a small $0 discovery experiment. Confirm actual source responses and saved records. Save the daily schedule only after choosing its employer/state scope and budget. Cloud Scheduler invokes the background worker every five minutes; the per-user schedule chooses when an experiment is due.

Optional licensed web search requires `BRAVE_SEARCH_API_KEY` and `BRAVE_QUERY_COST_MICROS` on both the web service and research job. Keys belong in Secret Manager. A microdollar is one millionth of a dollar. Use the subscription's actual marginal price; the app does not claim a universally free search quota. The ledger marks these charges as configured estimates until reconciled with actual provider billing.

## Source constraints

- [IRS distribution rules](https://www.irs.gov/retirement-plans/plan-participant-employee/401k-resource-guide-plan-participants-general-distribution-rules): separation and plan-permitted in-service distributions are relevant routes; age alone does not establish an available eligible distribution.
- [DOL datasets](https://www.dol.gov/agencies/ebsa/about-ebsa/our-activities/public-disclosure/foia/form-5500-datasets): the data describe plans and sponsors. Coverage is not universal, and a form-year dataset can contain other plan years.
- [FEC use restrictions](https://www.fec.gov/updates/sale-or-use-contributor-information/): this prospect pipeline excludes individual contributor records, including using those records to verify commercial lists. The FEC discusses distinct exceptions for bona fide noncommercial academic research.
- [LinkedIn OpenID Connect](https://learn.microsoft.com/en-us/linkedin/consumer/integrations/self-serve/sign-in-with-linkedin-v2): member sign-in is not an arbitrary prospect-search entitlement.
- [Brave Search API](https://api-dashboard.search.brave.com/app/documentation/web-search/get-started): optional licensed search. Source snippets never qualify a lead automatically.

Scout and OpenOutreach were inspected as references. No source code from either project was incorporated. The source application retains its Node/PostgreSQL architecture and user-controlled provider subscriptions.
